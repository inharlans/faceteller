FaceTeller 전체 release 수용 계획 — 2026-10-14

이 문서는 시험계획이며 합격 보고서가 아니다. requirements.json의 28개 요구사항과 아래 A01~A24를 연결한다. 기존 pilot 통과를 새 release 통과로 승격하지 않는다. 현재 GPU 비교45회는 main 전용이며 동결 유지한다. 이 감사에서 모델/서비스를 실행하지 않았다.
규범 순서: current-directive 및 최신 사용자 승인 > 상세설계 제출본 > 요구사항 제출본 > HTML 목업. 인간 검수는 제외한다. AI/자동 검증·weak label 상태와 독립 human GT=0을 표시하며, 인간 검수를 요구하는 승인 단계는 추가하지 않는다.

실행 순서와 담당
지금 가능한 CPU 단계: 출처/manifest/순수함수/API fixture/독립 PostgreSQL/schema/새 레이블·crop 정합성 검사. 데이터·모델 변경은 별도 release 버전에서 수행한다. main의 benchmark 완료 후 main이 새 모델·전처리·깊이·PG를 연결하고 GPU 수용시험을 수행한다. 문헌 corpus·번역·조건 정의는 Claude 담당; 본 계획은 그 산출물의 수용 계약을 정의한다.
신규 parsing/extended labels는 사용자 추가 승인에 따라 독립 worker가 CPU에서 담당한다. 이마/귀/visible pigmented marks의 정확한 정의와 라이선스/unknown 정책을 먼저 고정한다. under_eye, philtrum_definition, 기존 v3 항목은 main 담당이다.
결과 artifact는 새 release 전용 경로에 test ID, source/model/schema/preprocess/corpus hash, 환경, 데이터 종류(fixture/실제), split, 표본수, pass/fail/blocked/not_run, 실패근거를 기록한다. 실제 사용자 요청 사진·좌표·분석이력 저장 없이 수용시험 집계만 보존한다. 승인된 오프라인 K-Face 연구 산출물은 접근통제된 영역에서 별도 관리한다.

A01 — SSOT/승인 변경 추적 [CPU 문서]

A03 — 신규7영역 target/weak 주석 [CPU/local]

A04 — 설계 전처리와 학습/서비스 parity [CPU]

A05 — 실제 카메라/자동 캡처 [CPU 브라우저+실제웹캠]
권한 허용/거절/장치없음, 얼굴없음/여럿, 방향·크기·밝기 각각 실패, 유지 도중 이탈, 늦은 이전방향 응답, 화면숨김/이탈을 실행한다. 조건 전부 연속유지 시 방향마다1회, 순서 front→left→right, 3장 후 submit1회. 모든 실패조건은 gauge reset와 구체안내를 보여야 한다. 실제 영상 표시 중단 여부를 확인하고 처리fps/지연을 보고하되 SSOT에 없는 최소fps 수치를 발명하지 않는다. detector adapter 없는 fixture만으로 합격 불가.

A08 — 메모리/취소/예외 수명 [CPU fault injection, main 실자원]

A09 — 모델 패키지/새영역 학습 [main GPU; CPU metadata]
현재45회 공통절차/seed/입력/split을 보존한다. 선택보고서는 기존15head pipeline만 다룬다. 새 전처리·새head 학습은 별도 버전, weight/schema/class-index/preprocess hash로 결합한다. 모든 지원head의 실제weight/클래스지원/검증근거를 요구한다. unknown target을 특정class로 채우지 않는다. 새pipeline 최적백본을 주장하려면 그pipeline에서 비교해야 한다. 목표정확도 수치는 SSOT에 미확정이므로 최종평가를 보기 전에 main이 항목별 acceptance를 명시하며, 사후 결과맞춤 기준은 금지한다.

A10 — 보정/선택 낙관성 [CPU 평가; main 추론]
선택34로 checkpoint와 후보선택, 보정34에서 frozen checkpoint/candidate별 T, test62는선택동결후. macro-F1은 truth/pred 합집합 정책(둘다없으면제외) 고정. accuracy/F1/NLL/Brier/ECE 및 class support, unknown 제외수, 전체/확정 coverage를 함께 보고한다. validation 재사용의 낙관성·small N·AI정답·test기관찰을 명시한다. 새crop/model에 옛T 재사용 시 합격 불가. calibration 성능을 독립 정확도증명으로 쓰지 않는다.

A11 — 깊이 의존성·400분포·점수 [CPU 기하+main 실영상]
VGGTEngine.infer는3RGB만 받고, measure_geometry에서 동일좌표계 특징점과 결합하는지 검사한다. 4개상대비율은 길이단위가 아닌ratio. 등방scale/공통회전/이동 기하검사, finite/퇴화/경계밖/가림/방향오류/양측뒤바뀜을 검사한다. low:r<b1, medium:b1≤r<b2, high:r≥b2; P1=Phi((r-b1)/sigma),P2=Phi((r-b2)/sigma); scores=(1-P1,P1-P2,P2), 선택된 hard label의 score를 사용하고 score argmax로 label을 뒤집지 않는다. b1<b2/sigma>0/유한/score범위와합을 검증한다. score와confidence=null/정답확률아님을 보존한다. 400명분포 경계는 승인된 기술통계이고 test-independent calibration이라 부르지 않는다. 품질 gate는 finite만으로 충분하다고 확정하지 말고 반복/가림/시점일관성으로 사전정의한다.

A12 — 깊이 부분실패 보존 [CPU injectable engine]
정상CNN 후 깊이 OOM/추론예외/한항목점퇴화/사선특징점실패를 주입한다. 복구 가능한 깊이실패는 관련항목만HELD+사유, CNN/문헌은 유지한다. 전체preprocess불가는422, 복구불가능서버장애는명시error. 현재 ActualService의 engine.infer 예외는 전체error로전파되므로 이 경로는 release gap이다.

A13 — DecisionPolicy [CPU]
confidence==theta 확정/<theta 보류, binary.60/multiclass.50 하한, 미보정/NaN/가림/label없음/measurement score없음/품질불량을 검사한다. HELD label 제거·문헌조건제외. 확정0은REINPUT_REQUIRED, 일부보류PARTIAL, 모두확정COMPLETE. 확정있고문헌0은정상NONE이며 재입력 아님. thresholds는 validation만 사용하고 운영값/버전을 기록한다.

A14 — mixed G/AND/제한 parity [CPU fixture+실제PG]
CNN.81+depth.04→G=.18, explicit classification_only→.81. depth-only가 자기점수로순위경쟁, 0포함→G0, 잘못된score/보류조건은선정불가. AND전체조건누락·OR를임의평탄화·중복충돌을 검사한다. 동률문헌우선순위/조항순서/numericID 결정성, 다부위조항은관련모든부위에서1개씩집계, 최대3/전체5. API/Memory/PG가동일passageID·G·components·rank를 반환해야 한다. 기존 독립PG34checks를 새데이터로재검증한다.

A16 — 전체 corpus와조건 [Claude 산출물; CPU 검증]
