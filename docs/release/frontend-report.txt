- 순위·G·score_components는 서버 값을 그대로 표시한다. 종합 일치점수와 깊이 경계점수는 100점 환산하며 정답확률과 구별한다. 분류 confidence와 깊이 measurement_score를 혼동하지 않는다. 원자료의 review_status도 표시한다.

촬영 / 업로드
- MediaPipe Face Landmarker 0.10.32를 classic Web Worker에서 CPU delegate로 실행한다. 메인 React 스레드에서 검출을 실행하지 않는다. numFaces=2로 복수 얼굴을 거부하며 특징점·표정 지표는 워커 내부에서만 사용한다.
- 미리보기·검사·캡처 모두 비반전 영상이다. MediaPipe column-major 4×4 행렬에서 xyz Euler를 추출한다. 좌측 사선 yaw<0, 우측 yaw>0이며 화면 기준 안내 화살표를 제공한다.
- src/capture.ts ACQUISITION에서 기본값을 조정할 수 있다: 정면 |yaw|≤12°, 사선 |yaw|=20..60°, |pitch+5|≤16°, |roll|≤12°, 얼굴 폭≥150px 및 프레임 폭 대비 .25..80, 얼굴 영역 평균 밝기45..235, smile≤.3, blink≤.5. 사선 좌우는 반대 부호가 되도록 검사한다. 이 값은 공유한 촬영 기본값이며 과학적으로 검증된 분류 정확도 기준이라는 주장은 하지 않는다.
- 800ms AND 최소8개 새로운 프레임을 연속 충족해야 캡처한다. 이탈·300ms 초과 프레임 간격·중복 프레임·400ms 초과 지연 결과는 누적을 초기화한다. 세대 토큰으로 이전 방향·이전 이용 흐름의 결과와 캡처 완료를 거부한다. 검사에 통과한 바로 그 비반전 snapshot을 JPEG로 캡처한다. 방향당 1회, 3장 후 분석 요청 1회이다.
- 권한 거부는 업로드로 안내한다. 화면 이탈·페이지 숨김·트랙 종료·취소·3장 완료 때 stream/worker/timer를 정리한다. 늦게 승인된 getUserMedia 스트림도 즉시 종료한다.
- 업로드는 JPEG/PNG/WebP, 장당10MiB, 최소160×160px, 최대2400만 화소를 검사하고 디코딩 및 로컬 얼굴·방향·크기·밝기·표정 검사를 수행한다. 검사 이미지의 긴 변은 최대1600px로 줄이지만 서버에는 사용자가 선택한 원래 파일을 전송한다. 검사 실패는 해당 슬롯에서 재선택하도록 안내한다. 세 슬롯이 모두 통과하면 촬영과 동일 API로 자동 요청한다.
- 사진은 React 흐름의 메모리에만 존재한다. 파일 입력 DOM의 FileList를 즉시 비우고, 교체·삭제·전송·이탈 때 object URL을 폐기한다. localStorage/sessionStorage/IndexedDB/서비스워커/분석 이력 저장/사진 로그/분석 로그/외부 AI 호출은 구현하지 않았다. 테마도 메모리 상태만 사용한다.

백엔드 연결 계약 (메인 담당자 전달 완료)
1. frontend/dist를 웹 루트 /에서 제공한다. /api 라우트와 /assets 정적 파일을 SPA fallback보다 먼저 연결한다. 동일 origin 사용이며 서브경로 배포는 현재 설정 대상이 아니다.
2. POST /api/v1/analysis, multipart fields front,left_oblique,right_oblique,input_mode(camera|upload). Content-Type boundary는 브라우저가 생성한다.
3. application/x-ndjson: progress(stage), result(data), error(code,message,direction). 기존 stage 5종을 사용하며 서버에서 온 실제 진행만 표시한다. HTTP4xx/5xx의 NDJSON 오류도 읽는다. UTF-8 byte 경계, 마지막 개행 없음, 연결 중단, 잘못된 JSON, 중복 terminal을 처리한다. 중단을 성공으로 표시하지 않는다.
4. COMPLETE/PARTIAL/REINPUT_REQUIRED, items와 passages, source, evidence_item_ids, G/rank/score_components 기존 계약을 사용한다. 재입력·오류·취소는 임시 사진을 비우고 원래 입력 방식으로 복귀한다. 카메라는 다시 촬영 버튼을 기다린다. 권한/카메라 자체 오류는 업로드로 안내한다.
5. /assets/mediapipe/vision-worker.js
   /assets/mediapipe/face_landmarker.task
   /assets/mediapipe/wasm/* (npm tasks-vision의 wasm loader 및 wasm 파일)
   실제 파일은 frontend/public/assets/mediapipe에 있으며 build가 dist로 복사한다.
6. MediaPipe 모델 SHA256: 64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff
   모델·WASM은 최초 준비 때만 다운로드/복사하며 실제 브라우저 사용 중에는 동일 origin 자산만 읽는다. Noto Sans KR / Serif KR / Serif TC 글꼴도 로컬 번들이다. 외부 폰트 CDN을 호출하지 않는다.
7. 개발 서버는 http://127.0.0.1:5173, /api proxy 기본 http://127.0.0.1:8767. FACETELLER_API 환경변수로 개발 upstream 변경 가능. 배포는 HTTPS 또는 카메라가 허용되는 localhost가 필요하다.

인쇄 정책
- 결과와 동일한 AnalysisResult로 인쇄 컴포넌트를 만든다. 원문·직역·출처·순위/G·주요 판정과 근거·비예측 안내를 인쇄한다. 상세 해설과 점수 구성요소 목록은 제외한다.
- 주요 판정은 선정 조항 evidence_item_ids에 연결된 확정 항목이다. 문헌이 없을 때는 첫 확정 항목 최대5개이다. 전체 확정·보류 개수와 전체 판정/사유는 화면에서 확인하도록 안내한다. 모든 항목 45개 등을 무조건 한 장에 덤프하지 않는다.
- A4 10mm 여백, 본문190×277mm. 로컬 글꼴 준비 후11pt부터8pt까지 실제 본문 높이·폭을 검사한다. 생략부호, 글자 절단, 숨김 overflow 없이 원문·직역을 전부 보존한다.
- 한 장 한계를 넘으면 초과를 알리고 한 장 인쇄 버튼을 막는다. 본문을 유지하는 여러 장 인쇄를 제공한다. 무제한 분량을 한 장으로 출력할 수 있다고 주장하지 않는다. 브라우저 직접 인쇄에서도 넘친 본문을 잘라내지 않는다.
