GPU 순서와 CLI
queue는 이전 subprocess 종료 후 release-labels / waiting_for_reviewed_automatic_label_artifacts를 게시한다.
waiter는 이 조합에서만 Qwen smoke를 시작한다. comparison/depth running/failed 및 잘못된 status에서 호출0회 확인.
Qwen smoke/all은 .venv-labeling/Scripts/python.exe, 병합/registry/tests는 waiter의 sys.executable을 사용한다.
따라서 main은 .venv/Scripts/python.exe로 waiter를 실행해야 한다.
subprocess.run(check=True)는 순차 완료를 기다리고 실패하면 marker 전에 중단한다.
Qwen all subprocess가 종료된 뒤 두 CPU 병합, registry, parity, CPU tests를 거쳐 marker를 원자적으로 쓴다.
queue는 marker 전까지 다음 release training을 시작하지 않으므로 정상 단일 queue에서 GPU가 겹치지 않는다.
잠금은 waiter 중복을 방지한다. 다른 수동 GPU 작업/중복 queue까지 통제하는 시스템 전체 GPU lease는 아니다.
운영 전제는 main이 기존 단일 queue를 유지하고 별도 GPU 프로세스를 동시에 시작하지 않는 것이다.

landmark 19개 검토와 누수 회귀시험
현재 schema의 source=landmark 특징은 정확히19개다. fit_feature의 fit 입력은 train_ids에 해당하는
참가자 중 유효 반복>=3인 표본뿐이다. 15개 일반 특징은 TRAIN 참가자 median의 quantile,
eye_tilt/brow_tail/mouth_corner는 물리적0, lip_balance는 물리적1을 중심으로 TRAIN 반복 변동만 사용한다.
각19개에 대해 selection/calibration/test 값과 반복 수/분산을 극단적으로 바꿔도
fit 결과와 TRAIN labels가 동일함을 확인했다. TRAIN 자체 변경은 결과를 바꾸는 양성 대조도 통과했다.
모든4개 물리 중심에서 low/level/high class 방향, 중심값, boundary unknown을 확인했다.
실제 산출물의 중심 주변 경계:
eye_tilt: [-1.6650614570670872, 1.6650614570670872]
brow_tail: [-1.3942755120632653, 1.3942755120632653]
mouth_corner: [-0.018611051891541074, 0.018611051891541074]
lip_balance: [0.902941815102114, 1.097058184897886]
입술/입꼬리는 mouth quality gate 때문에 train fitting269명, 눈/눈썹은270명이다.

새 brow endpoint는 각 눈썹의 바깥/안쪽 upper·lower 평균 endpoint를 비교한다.
이미지 y가 아래로 증가하므로 inner.y-outer.y가 양수일 때 바깥 꼬리가 더 높은 ascending이다.
양쪽 모두 sign이 일치하고, 중간 arch만 이동해도 endpoint tilt는 바뀌지 않는다.
평행이동/등방 scale/roll 회전에 대한 synthetic geometry invariance도 통과했다.
이 항목은 기존 lateral-third arch descent와 다른 관찰량이며 기존 모델과 같은 표적이라고 주장하면 안 된다.
19개 landmark feature와 기존 visual soft vote key의 교집합은 없어 새 hard label을 오래된 soft vote로 덮지 않는다.

남는 한계와 운영 해석
18/20 strict JSON 성공은 문법·입력 실행 가능성 기준이며 의미 정확도 기준이 아니다.
TRAIN 각 클래스>=2, selection/calibration known>=2는 비어 있지 않은 학습 최소 조건일 뿐이다.
validation/calibration에 단일 클래스만 남을 수 있으므로 클래스별 support/missing class를 반드시 보고한다.
test support가 readiness를 결정하지 않음을 별도 시험했다. 역사적 test62의 retrospective 성격은 그대로다.
한 VLM의3조명 응답은 독립3평가자도 아니고 인간 검수 정답도 아니다.
1.96*TRAIN repeat SD/sqrt(n) guard는 상관된 조명 반복의 휴리스틱이며 검증된 median 신뢰구간이 아니다.
registry builder는 landmark protocol을 강제 확인하지만 landmark 내부 schema/implementation 해시를
매번 재검증하지는 않는다. 이번 실제 파일은 모두 일치함을 별도로 확인했다. 이후 generator/schema를 바꾸면
landmark artifact를 다시 생성하고 새 readiness를 통과해야 한다.
train source hash freeze는 라벨/프로토콜 파일을 고정한다. 전체 crop binary를 매 epoch 재해시하는 계약은 아니다.
공유 crop/라벨을 readiness 후 변경하지 않는 운영 조건이 필요하며 full SSOT/실서비스 합격 주장을 대신하지 않는다.
