범위
scripts/release/build_report.py만 실행 코드를 추가했다. 이 안내 외에 기존 모델,
평가기, 백엔드, 프런트엔드 또는 원본 설계 문서를 수정하지 않는다.
CPU에서 JSON을 읽고 ReportLab/OpenPyXL로 집계한다. torch import, 가중치 로드,
학습, GPU 연산, 서비스 요청, 데이터베이스 접속은 하지 않는다.
실제 보고서는 아직 생성하지 않았다. 실제 필수 산출물이 모두 준비된 후 메인이 실행한다.

실행 (프로젝트 루트 / Windows venv)
  .venv/Scripts/python.exe -B scripts/release/build_report.py --validate-only
  .venv/Scripts/python.exe -B scripts/release/build_report.py

첫 명령은 입력·해시·400명·집계·개인정보 검사만 한다. 두 번째 명령은 검사 후
PDF/XLSX/TXT를 함께 생성하고 Downloads 공유 폴더로 복사한다.
--no-copy: 프로젝트 출력만 생성. --output-dir/--share-dir: 출력 위치 명시.
--root: 입력 프로젝트 경로. --corpus: 다른 corpus 파일을 명시할 때 사용.
기본 corpus는 실제 producer 경로인
data/release/literature/reference_corpus_v1.json이다(corpus.json 자동 추측 없음).
필요 패키지: reportlab, openpyxl. Windows venv에 설치되어 있음을 확인했다.
기본 글꼴: C:/Windows/Fonts/malgun.ttf 및 malgunbd.ttf. --font-dir로 변경 가능.
파일·stdout·stderr 모두 UTF-8을 명시한다.

해석 원칙
- 자동 참조/AI 합의 레이블 일치도이며 전문가 정답 또는 관상/운명 정확도가 아니다.
- 62명은 역사적 시험 집합. 학습군 포함 400명 전체 HTTP 검증을 독립 시험으로 부르지 않는다.
- 기존 3계열×5부위×3시드 45회 비교와 새로운 범위/전처리의 release 결과는 별도다.
  45회 비교 보고서나 모델/평가기는 이 작업에서 수정하지 않았다.
- F1은 참조/예측 클래스 합집합 기준. 참조 지지수 0 유형은 재현율 평가불가.
  헤드 평균은 유효 헤드 동일 가중, 온도 전후 비교는 같은 평가 가능한 헤드끼리다.
- 새 release history는 train_seconds와 validation_seconds를 기록한다. 모든 epoch에
  검증 시간이 있으면 실제 합계를 제공하고, 과거 기록에 없으면 미기록으로 표시한다.
  학습합·검증합·elapsed_seconds 전체 경과를 분리한다. elapsed−train을 검증시간으로
  추정하거나 이번 실행 시간을 새로운 전체 파이프라인 소요시간으로 주장하지 않는다.
- 배포 train_support는 가시성/crop 조건을 충족한 유효 학습 인물 지지수다.
  registry의 원본 참조 지지수와 같을 것을 요구하지 않으며 더 적을 수 있다.
  클래스별 표에서 두 값을 별도 열로 표시한다. 원본 참조보다 큰 값은 모순으로 거부한다.
- registry.thresholds가 제공되면 측정 metric·경계 방법·물리 중심·실제 경계값·
  적합 분할/유효 인물·보류 규칙을 주석출처 시트에 기록한다. 방향형의 0 중심과
  입술 비의 1 중심을 인구 분위수로 오해하지 않도록 설명한다. 눈썹 꼬리의
  brow_outer_inner_tilt를 반영하며 지지수0 유형의 독립 양성 검출 능력은 주장하지 않는다.
- len(history)==epochs_max와 selected_epoch==epochs_max는 별도 항목이다.
- HTTP 시간은 전송 전부터 NDJSON 종료까지. 서버 계측 단계 합과 구분하며,
  수신 완료 후 전체 처리시간과 동일하다고 주장하지 않는다. 예열은 별도 집계한다.
  p95는 (n−1)×.95 위치 선형 보간. >5초 건수를 실제 측정값에서 센다.
- 최신 timings의 alignment_seconds도 단계 합에 포함한다. 별도 연속 계측인
  received_to_result_seconds는 필수이며 수신 완료 후 디코딩부터 결과 준비까지다.
  최종 NDJSON 직렬화/전송/정리는 제외한다. HTTP 총시간과 각각 평균/p95/최대/초과를
  보고하며 실제 클라이언트 수신 시점과 혼동하지 않는다.
- 깊이 기준은 all400의 기술적 분포이며 실제 3D 정답이 아니다. sigma는 학습군
  반복 측정, 품질 기준도 학습군 기반이다. 종합 G/깊이 경계점수는 정답확률이 아니다.
- 실제 PostgreSQL 응답 대조, 합성 UI/카메라 상태 테스트, 실서버 합성 오류 입력을
  구분한다. 실제 사람 웹캠 또는 전 문헌의 모든 조건이 검증되었다고 일반화하지 않는다.
- 원 VGGT-1B는 비상업용이다. 별도 Commercial 체크포인트의 허용 범위를 적용하지 않는다.
