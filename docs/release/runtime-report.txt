Preprocessing, inference and partial failure
Original decoded RGB images and original-pixel MediaPipe detections feed the shared
release_preprocess functions. Training/runtime both use eye-centre normalization,
isotropic crop/letterbox and network_array. Changes to the main-owned shared
forehead crop are automatically used; no copy of old crop geometry is embedded.
ImageNet normalization precedes inference. Softmax probabilities are averaged
equally across architectures and available valid bilateral crops (valid_fraction
>=0.9), then the feature's own T applies exact normalized p**(1/T). Zero probability
remains zero; no logit averaging or average of separately calibrated confidences.

Bohr parser is local CPU-only ReleaseParser(threads=2); parse(image,landmarks) returns
the original-coordinate mask. Mask is only a visibility/geometry aid; original RGB
is unchanged, never skin-masked. Ear box comes from visible_ear_box and ear_metrics
quality. C4=ear_left_oblique mirror=False; C10=ear_right_oblique mirror=True, matching
training. Missing or unreliable ear sides are excluded individually. Forehead
visibility uses forehead_metrics reasons. visible_mark_candidates quality gates the
mole/visible-skin-mark head; candidate coordinates are discarded and never returned,
logged or stored. Detector scores/weak geometric measurements never become CNN
confidence. Skin marks are a limited visible morphology task, not clinical diagnosis.
Pose/scale/illumination checks cover all12 regions; smile/blink/frown/open-mouth
checks explicitly extend to under_eye/philtrum/cheekbone/forehead/glabella. No legacy
five-region-only quality scope is reused. These gates are heuristic/weak visibility
checks and do not claim independent occlusion/quality ground-truth validation.

A missing crop, model exception in one part, invalid head output, unsupported
predicted class, or uncalibrated rare head holds only affected items. Exceptions are
caught as Exception, never cancellation BaseException, for partial inference.
Depth uses release_depth.estimate(engine,images,detections,detect): original whole
images are framed internally by MediaPipe OVAL1.5; VGGT518 and re-detection match the
new cohort protocol. release_depth.observations supplies depth membership scores.
A depth failure produces held depth items and continues CNN decisions/DB matching.
No old boundaries, human GT claim, classifier-confidence reinterpretation or raw
landmark coordinates are introduced. Runtime keeps a failed request error generic.

Memory lifecycle
One inference worker serializes shared MediaPipe/parser/CNN/VGGT resources. A
cancelled request waits for its nonpreemptible worker before closing its PIL images,
crop images and detection lists; repeated task cancellation is covered by tests.
InputSet bytearrays are cleared by pilot_contract's existing response finalizer,
including validation/response failures. The VGGT wrapper closes prepared PIL images
if inference raises; the shared release_depth closes them on successful inference.
Startup/shutdown also close owned resources. There is no request image/history
database, temporary face image, outgoing face request or analysis logger.

Browser acquisition consistency review (CPU/static review, 2026-10-14)
Main reported a real CPU browser upload of the first sorted train participant:
original864x576, landmark bounding-box width156.7px, ratio0.181, acceptable front pose.
The original browser gate rejected this solely because its camera framing ratio was
also applied to upload. This observation is main-reported, not independently rerun here.
Design3.3 requires camera face/direction/size/brightness guidance;3.4 requires upload
format/size/decode/face checks and the same downstream API. Neither specifies150px
or ratio0.25..0.8. A camera-only framing-ratio gate is compatible with those sections;
these numerical thresholds remain implementation choices, not design-mandated values.
No frontend files were edited by this reviewer. Main is implementing the mode split.

Remaining consistency findings observed before/during that change:
1. Browser150px means clipped horizontal all-landmark bbox width; release backend150px
   means Euclidean234-to454 distance on the FRONT image. Passing one does not prove
   passing the other. The stated156.7px bbox alone cannot establish backend eligibility.
2. decodeFile can reduce only the inspection ImageBitmap to longest-side1600 while
   Upload keeps/sends the original File. An absolute pixel gate therefore uses a
   different scale for large images. Use a documented original-pixel coordinate
   scale/width definition or explicitly document a stricter browser gate; do not
   silently crop or enlarge inputs simply to pass. Existing864x576 case is unscaled.
3. Browser hard-gates all three views on size/pitch/roll/brightness/expression;
   release backend uses frontal size/pose, scoped HELD reasons and separate oblique
   checks. Removing the ratio alone does not make acceptance behavior equivalent.
4. Browser brightness is weighted RGB over the face bbox (45..235); backend currently
   uses whole-front-image PIL grayscale mean >=45. Background and pixel coefficients
   differ, and backend has no matching upper-brightness/roll gate. This is a policy
   distinction that needs explicit accounting in acquisition vs inference reports.
5. Production executes the bundled public/assets/mediapipe/vision-worker.js: mode must
   pass Upload->VisionPort->worker->quality, and the worker plus dist must be rebuilt.
   Unit-testing capture.ts alone does not verify the shipped worker or upload flow.

Independent response selection proof (CPU verification, 2026-10-14)
scripts/release/verify_service.py now validates every successful HTTP result against
the complete AND-matched candidate set in one read-only DB revision snapshot:
- every required label has exactly one CONFIRMED feature; no held evidence is used;
- evidence_item_ids matches the complete sorted required-label list exactly;
- score_components has one entry per required feature and exactly matches the
  response item's CNN confidence or depth measurement_score, with the correct kind;
- independent G = exp(fsum(log(scores))/n), or exactly0 if any score is0; no epsilon,
  ignored depth scores, feature pooling, arithmetic mean or product underflow;
- independent ordering by descending G, literature_priority, passage_order and
  numeric/string passage ID; greedy cap3 for EACH participating region and total5;
- actual selected IDs and order equal the independent full-candidate selection,
  including the case where a valid candidate was silently omitted;
- rank/count/score-mode metadata and unchanged DB text/source are validated;
- the production PassageSelector is additionally cross-checked against the
  independent selection and G calculation, not used as the sole arithmetic oracle.
Corruption raises an error before that response is recorded as verified.

Output remains outputs/release/service-verification.json, schema v1 with additive
fields (no original text, images, landmarks or measurement coordinates persisted).
Per participant and separate warmup row:
  score_formula_verified: bool
  score_formula_verified_count: number of selected passages whose formula passed
  score_components_verified_count: total required feature components checked
  selection_verified: bool
At report top level and each split_summary entry, the two counts are summed over
participants only; score_formula_verified is true only when every participant row
passed, and selection_verified_participants counts successful selection checks.
Errors carry false/0; legitimate empty selections carry true/0. Therefore a true flag
with count0 proves empty-selection correctness, not a measured nonempty score case.
Warmup and error probes are excluded from participant totals. These are retrieval
consistency checks, not independent model accuracy, human GT or prediction validity.
