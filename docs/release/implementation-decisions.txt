FaceTeller 실제 구현에 적용한 결정
작성일: 2026-10-14

기준 문서는 FaceTeller_상세설계서_제출본.pdf다. 이후 사용자가 승인한 깊이 점수와 혼합 기하평균, 400명 전체 활용, 사람 검수 제외를 반영한다. 원본 설계 문서는 수정하지 않는다. 이 문서는 구현 결정이며 학습·검증 완료 보고서가 아니다.

1. 사진과 데이터 분할
사용자는 정면·좌측 사선·우측 사선의 사진 3장을 입력한다. CNN에는 해당 부위의 정면 사진을, 귀에는 사선 사진을 사용한다. VGGT에는 3장을 함께 넣는다.
400명은 학습270명, 모델선택34명, 신뢰도보정34명, 시험62명으로 구분한다. 동일인의 모든 조명·방향·양쪽 부위는 같은 집합에 둔다. 전체400명을 최종 서비스 실행에 활용하되, 학습한 사람의 결과를 독립 시험 정확도로 보고하지 않는다.
기존 시험62명은 이전 실험에서도 사용된 집합이다. 새 외부 사용자에 대한 성능은 별도로 검증해야 하며 이번 결과와 같다고 단정하지 않는다.

2. CNN 모델을 고르는 이유와 절차
ResNet18, EfficientNet-B0, ConvNeXt-Tiny의 공식 ImageNet 사전학습 가중치에서 미세조정한다. 기존 눈·눈썹·코·입·얼굴형 15개 시각 항목에 동일한 분할과 학습 절차를 적용하여, 세 초기값으로45개 모델을 비교한다.
평가 지표는 사람 단위 항목별 macro-F1, 정확도, 클래스별 표본수와 신뢰도 보정 지표다. 단독3종, 두 모델 조합3종, 세 모델 조합1종을 비교한다. 선택34명의 세 반복 평균F1에서 최고점과0.01 이내인 후보 중 실제 CNN 처리시간이 가장 짧은 것을 선택한다. 이 규칙은 시험 실행 전에 고정했다.
이 결과는 현재15개 시각 항목에서의 선택 근거다. 새 부위에서도 항상 최적이라는 뜻은 아니다. 선택한 구조를 새 전처리와 전체 분류 항목으로 다시 학습하고, 별도의 시험 결과를 보고한다. 비교용 가중치를 전처리만 바꿔 그대로 서비스에 넣지 않는다.

3. 전처리
두 눈의 중심을 잇는 선을 수평으로 맞추고, 눈 중심 간 거리를128픽셀로 맞춘 공통 좌표계를 사용한다. 각 부위는 이 좌표계에서 정해진 영역을 잘라낸다. 모델 입력 크기를 맞출 때 가로세로를 같은 비율로 조정하고 남는 부분에 여백을 넣는다.
학습과 서비스는 facework/release_preprocess.py의 같은 함수를 사용한다. 기존 얼굴 폭 기준 crop을 확대해서 새 데이터라고 부르지 않는다. 원본 K-FACE ZIP과 원본 좌표로 다시 추출한다.
귀는 얼굴 특징점에 가상의 귀 좌표를 추가하지 않는다. 사선 사진의 실제 귀 영역 분할 결과가 있어야 추출한다. 보이지 않는 귀는 보류한다.

4. 레이블과 신뢰도
기존의 회귀형 형태 항목도 해당 항목의 배타적 클래스를 예측하는 분류 출력으로 구성한다. 예를 들어 콧방울 너비는 좁음·보통·넓음 중 하나를 출력한다. 사람의 반복 사진에서 얻은 상대 형태 레이블과 기존AI 시각 주석을 학습 목표로 사용한다.
초벌 주석, 알고리즘으로 계산한 주석, 사람이 확인한 정답을 구분한다. 이번에는 사용자 지시에 따라 사람 검수를 하지 않으며, 독립적인 사람 정답 수는0이다. 정확도는 자동 주석과의 일치율이라는 한계를 함께 기록한다. unknown과 borderline을 임의의 보통 클래스로 채우지 않는다.
신뢰도보정34명으로 항목별 temperature를 구한다. 배포 모델이 여러 개면 모델·좌우 부위 확률을 평균한 뒤 해당 평균에 맞춘 보정을 적용한다. 기본 확정 기준은0.60이다. 학습 표본이 없는 클래스를 높은 확률로 예측하더라도 확정하지 않는다.
애교살은 기존400명 중 뚜렷한 사례가8명뿐이다. 점 항목은 사진에 보이는 작은 어두운 피부 표시를 기술하며, 의학적으로 점인지 진단하지 않는다. 이러한 항목의 표본수와 자동 주석 한계를 숨기지 않는다.

5. VGGT와 MediaPipe의 관계
VGGT 신경망은RGB 사진3장을 입력받는다. 얼굴 특징점을 신경망 입력으로 넣지는 않는다. 서비스에서는 MediaPipe가 얼굴 위치와 방향을 확인하고, VGGT 출력에서 코끝·콧대·입술·턱끝에 해당하는3D 위치를 선택하는 데 필요하다. 따라서 두 도구를 함께 사용한다.
서비스와 분포 구축에서 같은 얼굴 framing을 사용한다. MediaPipe 얼굴 윤곽을 감싸는 정사각형을1.5배 확장한 사진을 만들고, 종횡비를 보존하여518×518로 맞춘다. 예전 제공기관 얼굴 박스로 만든 분포를 새 입력에 그대로 적용하지 않고400명과 반복 촬영을 다시 실행한다.
4개 지표는 얼굴 안 기준 깊이의 차이를3D 바깥 눈구석 간 거리로 나눈 상대 비율이다. mm 단위의 실제 길이가 아니다. 코끝은 콧방울, 콧대 시작은 안쪽 눈구석, 입술은 입꼬리, 턱끝은 코밑을 기준으로 한다.

6. 깊이 점수
400명 값의25·75백분위수를 경계b1,b2로 사용한다. r<b1이면 낮음, b1≤r<b2이면 보통, r≥b2이면 높음이다. 모집단이 정확히 정규분포라고 가정하여 경계를 고정하지 않는다.
P1=Φ((r-b1)/σ), P2=Φ((r-b2)/σ)
낮음 점수=1-P1
보통 점수=P1-P2
높음 점수=P2
레이블은 경계로 결정하고 그 레이블의 점수를 사용한다. 점수가 가장 큰 레이블로 분류를 바꾸지 않는다. σ는 학습군의 같은 사람을 다른 조명에서 반복 측정한 값으로 계산한다. 서로 다른 사람의 얼굴 차이를 측정 오차처럼 취급하지 않는다.
이 점수는 해당 구간과의 적합도다. CNN의 정답 확률이나 실제3D 계측 정확도라고 표시하지 않는다.400명 전체 경계는 사용자가 정한 기준 집단의 기술통계이며, 독립 시험 평가로 부르지 않는다.
방향·표정·유한한 형상·깊이 출력 신뢰도·시점 간 일관성을 검사한다. 수치 품질 경계는 학습270명에서 정한다. 이는 오류가 큰 입력을 보류하기 위한 규칙이며 실제3D 정답을 확보했다는 뜻은 아니다.

7. 문헌 선택
조항의 필수 형태 조건이 모두 확정된 경우에만 후보가 된다. CNN 신뢰도와 깊이 적합도를 각 특징당 같은 가중치로 사용한다.
G=exp(sum(log(s_i))/n)
관련된 특징이n개일 때 그n개 점수의 기하평균이다. 점수 중0이 있으면G=0이다. 동일 조항은 중복하지 않고, G가 높은 순으로 전체5개와 부위당3개 이내를 고른다. 동률이면 문헌 우선순위·조항 순서·ID 순서로 정한다.
이 점수는 문헌의 형태 조건과의 일치 정도를 정렬하는 값이다. 복·성격·건강·운명의 가능성이 아니다. 원문·직역·해설·출처를 미리 DB에 저장하고, 요청 중 새 풀이를 생성하지 않는다.

8. 실행과 검증
실제 서비스는 React+TypeScript, FastAPI, PostgreSQL을 사용한다. API는 사진3장을 메모리에서 처리하고 NDJSON으로 실제 처리 단계와 최종 결과를 보낸다. 조회 전용 DB 계정으로 문헌을 읽는다. 요청 사진·좌표·사용 이력은 저장하지 않는다.
한 부위 또는 깊이 분석만 실패한 경우 해당 항목을 보류하고 나머지 결과를 유지한다. 입력 전체가 불가능한 경우에만 재입력을 안내한다. 분석은 가능하지만 문헌이 없는 경우 정상적인 빈 결과로 처리한다.
최종 검증은 전체400명의3장 입력을 실제HTTP와실제모델·DB에 통과시킨다. 목표5초는 모델이 메모리에 올라온 상태에서 측정하고, 초과 건수도 보고한다. 코드 테스트, 합성 입력 테스트, 실제 얼굴 실행을 서로 구분한다.

9. 모델·문헌 이용조건
현재 로컬 VGGT 원본 가중치는 연구용 checkpoint다. 공식 저장소는 상업용으로 별도의 VGGT-1B-Commercial checkpoint를 제공한다. 상업 운영 시 해당 가중치의 접근권한·조건을 확인하고 같은 전처리로 경계와 품질을 다시 계산해야 한다. 현재 원본 가중치를 상업용이라고 표기하지 않는다.
공식 근거: https://github.com/facebookresearch/vggt (2026-10-14 확인)
문헌은 고전 원문과 온라인 전사본의 출처·판본·이용조건을 보존한다. 새 번역은 자동 작성 여부를 표시한다. 원문을 확보하지 못한 문헌이나 형태 조건이 불명확한 조항은 완료했다고 표시하지 않는다.

10. 자동 형태 레이블의 재정의
기존 landmark 기준이 현재270명과 다른 옛 학습군에서 계산됐던 문제를 바로잡았다. scripts/release/prepare_landmark_labels.py에서 현재 학습270명의 반복 사진만 사용해19항목 기준을 다시 만든다. 검증·보정·시험 참가자는 경계 추정에 사용하지 않는다.
눈꼬리·눈썹꼬리·입꼬리 방향은 집단 백분위수가 아니라 실제 수평0도를 기준으로 한다. 위아래 입술 비율은1을 기준으로 한다. 학습군 반복 변동으로 중심 주변 허용폭을 두며, 경계 근처 표본은 unknown이다. 이 허용폭을 검증된 신뢰구간이라고 부르지 않는다.
눈썹 꼬리는 눈썹 아치의 바깥 구간 기울기 대신 양 끝점의 상대 높이로 정의한다. 일부 방향 클래스의 표본이0인 결과를 다른 클래스에 억지로 배분하지 않는다. 실제 학습에 사용된 부위 crop이 없는 참가자는 해당 head의 train_support에서 제외하며, 반복 이미지 수를 사람 수로 부풀리지 않는다.

11. 문헌 원문 보관과 서비스 조항
신상전편14권(고금도서집성 전재본), 허부상법16편·서문, 태청신감6권, 유장상법 두 판본 스캔 전사를 출처·해시와 함께 원문 보관 테이블에 둔다. 추가 조담경도 동일하게 보관한다. 원문 보관량은 번역·조건 주석 완료량과 다르다. 서비스는 별도의 적격 조항만 읽으며, 번역이 없는 원문에 임의의 번역 문구를 채우지 않는다.
문헌의 ‘눈썹이 눈보다 길다’는 조건을 단순한 집단 상대 긴 눈썹 레이블에 연결하지 않는다. 복합 조건의 일부만 측정한 경우도 적격으로 만들지 않는다. 반대로 흔한 물리적 방향이라는 이유만으로 맞는 조건을 제외하지 않는다. 클래스의 빈도는 뜻의 일치 여부와 별개다.
피부 표시는 이마·윗볼의 노출된 피부 범위만 판정하므로, 없음 결과를 얼굴 전체에 점이 없다는 문헌 조건으로 연결하지 않는다.

12. 양쪽 눈 비대칭의 학습 입력
- eye_asymmetry는 좌우 눈의 형태를 비교하는 레이블이다. 한쪽 눈 crop 두 장을
  독립 분류한 확률 평균으로는 좌우 관계를 직접 학습할 수 없다.
- 새 release에서는 eye_spacing과 같이 얼굴 전체 입력을 쓰는 face head에 배치한다.
  eye6/face7로 바뀌며 전체12부위·41분류 특성 수는 동일하다.
- 기존45회 모델 비교의 스키마/학습조건은 바꾸지 않는다. 변경된 release 모델은
  별도로 다시 학습·보정·평가한다. 실제 train cache와 runtime의 joint face 입력,
  이전 head 배치 checkpoint 거부를 CPU 회귀 검사로 확인했다.

- 후속 확인: eye_asymmetry의 모델 입력 part는face, 화면·문헌 조건의 region은eye로
  분리했다. 눈 깜빡임 사유는 해당 눈 비대칭 항목에 적용하고 다른 얼굴형 항목을
  같이 보류하지 않는다. 학습 face 입력도 눈 품질 필터를 적용해3230→3227개로
  줄었고 학습 인물270명은 모두 유지됐다. 선택/보정34명씩은 그대로다.

13. 로컬 HTTPS 실행
- 기본 실험 경로 HTTP127.0.0.1:8767은 유지한다. 선택 실행 -Https는8768에서
  Uvicorn이 직접 TLS를 처리한다. 별도 proxy에 사진 임시파일을 만들지 않는다.
- 개발용 자체서명 인증서/키는 사용자 LocalAppData의 제한된 폴더에 둔다.
  시스템 신뢰 저장소·방화벽·공개 바인딩은 바꾸지 않는다.
- 실제 GPU 서비스의 HTTPS 실행과 일반 브라우저 신뢰는 별도 확인 대상이다.
  CPU TLS handshake9개 검사 결과는 docs/release/tls-report.txt 참조.

14. 문헌 조건과 실제 측정값의 의미 대조
- 입술이 들리거나 뒤집힘(掀)을 앞쪽 돌출 깊이와 같은 조건으로 연결하지 않는다.
- 입 가장자리의 능선(有稜)을 윗입술 중앙의 M자 윤곽과 같게 연결하지 않는다.
- 위아래 입술이 각각 두꺼움은 합산 두께 하나로 확인하지 않는다.
- 상안면의 짙은 점상 자국은 얼굴 위 존재를 충족하지만, 문헌의 黑子/痣 범주와의
  외관상 대응은 별도다. 임상 진단이 필요하다는 뜻은 아니며 일반 표식 레이블로
  이 역사적 범주를 확정하지 않는다. 원문·직역은 보관하고 자동 매칭만 제외한다.

15. 실제 문헌의 CNN·깊이 결합 범위
현재 적격73개는 CNN조건만70개, 깊이조건만3개, 한 조항에 둘을 모두 요구하는0개다.
합성 조합 검사는 두 점수의 기하평균을 검증한다. 실제 응답에서는 두 종류의 후보를
같은 순위에 넣지만, 현재 문헌에 없는 조항 내부의 결합 사례를 검증했다고 하지 않는다.
소아 문답의 대상 조건·미측정 콧방울 세부조건·모호한 눈썹 표현을 빼서 사례를 늘리지 않는다.

16. 비교 실험으로 정한 CNN 구성
45회 비교 학습(3계열×5부위×3시드)을 마치고, 선택34명에서 최고 F1과0.01
이내인 후보 중 실제 CNN 평균 추론 시간이 가장 짧은 구성을 고르는 사전 규칙을 적용했다.
선정은 ResNet-18+EfficientNet-B0+ConvNeXt-Tiny 확률 평균이다. 선택 macro-F1
0.7412, 역사적 시험62명0.703(3시드 평균), 예열된5부위CNN105.10ms였다.
ResNet-18 단독은 선택0.7223/20.49ms여서 성능 허용 범위에 들지 않았다.
이는 기존15항목·기존 전처리의 계열 선택 근거다. 변경된 눈 정렬과 전체41항목은
별도로12부위×3계열을 학습·보정·평가하며 기존 결과를 그대로 승계하지 않는다.
전체 서비스5초 여부는 VGGT와 DB 등을 포함한 실제 HTTP 측정으로 판단한다.
원자료와 공유 보고서: outputs/model-selection-20261014/.

17. 실제 새 VGGT 반복 측정 결과
400명L1와40명L2/L3, 총480회 측정이 완료됐다. 경계는400명P25/P75, sigma는
그중 학습군26명의 반복 산포다. 값은 눈 사이 거리로 나눈 상대 비율이며 mm가 아니다.
조명3개 모두에서 같은 낮음/보통/높음인 비율은 코끝65%, 코뿌리62.5%, 입70%, 턱75%다.
코끝은L3에서L1보다 평균0.012428 높게 나와 학습 반복sigma와 비슷한 조명 편향이 있다.
따라서 연속적인 경계점수는 제공하되 모든 촬영에서 같은 분류를 보장한다고 적지 않는다.
정규성 검정p는 코끝0.000367, 코뿌리0.00000867, 입0.0547, 턱0.4583이었다.
두 코 지표는 정규분포라고 단정할 수 없다. 경험적25/75백분위 경계는 그대로 적용하며,
Phi 점수는 측정 변동을 부드럽게 반영하는 규칙이지 참된 정답확률이라는 뜻이 아니다.
원자료: data/release/depth_config.json, outputs/release/depth-stability.json.
기하학적 정답 mesh가 없어 절대 깊이 정확도는 평가하지 않았다. 시험 결과로 경계를 바꾸지 않았다.

18. 귀 길이 입력의 기준 크기 보존
기존 귀 bbox를 매번 같은 크기로 확대하면 귀 높이/얼굴 기준 거리라는 레이블의 정보가
사라진다. 귀 입력만 visible-ear-eye-scale-v2로 바꿨다. 눈 중심 거리/cos(yaw)를
기준으로128픽셀에 정규화하고 눈의 기울기를 정렬한 뒤, 귀 중심의 고정192×256 창을
자른다. 귀 bbox 크기에 다시 맞춰 확대하지 않는다. 귀가 잘리면 그 입력은 제외한다.
400명/2400측면사진 중2373개 귀 입력의 원본 재생성·픽셀·변환을 대조해 차이0을
확인했다. usable L1 인물399명, 양쪽귀392명이며 학습270명은 모두 유지된다.
측정 레이블·경계·인물 분할은 변경하지 않았다. 다른33개 모델은 유지하고 기존 귀3개
모델과 이전 보정·시험 결과는 별도 보관 후 귀를 재학습하고 전체 보정·시험을 다시 한다.
완료 전에는 수정된 서비스 실행을 대기한다. 모델별 귀 입력 버전 및 별도 동결 문서
해시를 검사하므로 옛 귀 가중치가 새 입력과 섞여 서비스되지 않는다.

19. 한 클래스만 있는 신뢰도 보정 자료
보정 집합에 한 클래스만 있으면 온도 최적화가 수치상 수렴해도 서비스용 보정 완료로
인정하지 않는다. release에서는 실제 관측 클래스가 둘 이상인 항목만 보정을 채택하며,
단일 클래스 항목은 원래 분류 성능·표본수는 보고하되 서비스 결과에서 보류한다.
이는 보정34명만 보고 정한 적용 조건이며 시험 결과나 비교45회 결과를 수정하지 않는다.
이번 피부 표시·애교살 항목은 이 제한에 해당할 수 있다. 실제 적용 항목은 최종
deployment.json의 single_class_calibration_support 상태로 확인한다.

20. 2026-10-15 ResNet 단일계열 및 보류 기준 조정
사용자 지시에 따라 서비스는 ResNet-18 12부위 모델만 사용한다. 원래 비교·학습 기록은
보존하고 inference_frozen.json으로 현재 선택을 별도 동결한다. 새 모델 재학습은 없다.
설계5.4의 항목별 기준값 조정을 구현했다. 온도 보정에 쓴 보정34명에서만 후보 기준값을
비교하며 시험62명은 조정에 사용하지 않는다. 정책은 오확정 비용1, 보류 비용0.25로
고정했다. 즉 오확정1건을 보류4건과 동일한 운영 비용으로 보는 선택이며 통계적 진리가
아니다. 후보0.50~1.00(0.05간격), 2클래스 하한0.60/3클래스 이상 하한0.50이다.
평균비용 최소, 동률이면 확정수 최대, 초기0.60과 가까움 순으로 결정한다.
미보정 항목4개는 계속 보류한다. 같은34명에서 온도와 기준을 정하므로 개발 최적화이며
독립 정확도 증거가 아니다. 정책 JSON을 새 평가 전에 고정하고 후보별 오확정·보류를 남긴다.

21. 실제 입력 검사 정합성
원본 사진의 검은 배경 때문에 얼굴이 밝아도 전체영상 평균이45 미만인 사례를 확인했다.
서버 밝기는 얼굴 특징점 bbox 영역48x48 RGB휘도 평균으로 바꿨고 화면과 같이45~235를
사용한다. 얼굴 폭은 특징점bbox150px 이상을 유지한다. 좌측yaw[-60,-20], 우측[20,60],
pitch=-5±16, roll±12를 서버에도 적용한다. quality_version=face-roi-and-signed-poses-v3.
중간 HTTP실행은 원인·개수·해시를 기록해 보존하고 최종모델과 수정코드로 다시 실행한다.
